## Menu fill (PR 1)

Menus, overlays and the intro are authored at 4:3; in anamorphic
widescreen mode the game renders them pre-squeezed into the central 75% of
the wide frame with black side bars baked in, and no presenter scaling can
remove them. `cover` follows the game's own widescreen option (options
word at 0x535610, bits 20–21 = 2) and shows the central region of the
frame filling the window:

- **Races**: the race world at `gp` - 0x848 is null until a race is
  loaded; its game module (+0x84) then holds the AI race manager (+0xc)
  whose first word is the race state (2 = game init, 4 = countdown,
  5 = racing/free ride — `gamecomm.rs`, `racestate.rs`). Races never fill.
- **Pause menu**: the audio system's pause flags at `gp` - 0x6a0, bit 0 —
  verified live (the word flips to `0xffffffdb` while paused). The pause
  menu fills like the other front end screens.
- The FE menu flow word (`gp` - 0xb5c, `pluginmenu.rs`) does NOT change
  between front end and race in practice (stayed 0 through a whole
  race) — do not use it as an in-game detector.
- **Presenter crop**: both present shaders (texture path and the `emu-gs`
  buffer path) take a crop uniform (offset x/y, scale x/y) as group 1; one
  shared uniform buffer serves every pipeline; the settings overlay binds
  an identity crop (never cropped), and the identity is uploaded at
  creation (an unwritten uniform presents black — found the hard way).
- **Geometry**: the menu occupies the central 75% of the frame width at
  full frame height. `SSX3_MENU_FILL_HEIGHT` tunes how much height the
  fill shows: 0.75 = exact 16:9 fill (no distortion, cuts ~12% of the
  menu's top and bottom); the default 0.88 trades a small horizontal
  stretch for keeping the menu's title and button hints visible
  (user-approved proportions). The F10 overlay lists `cover`.

Verified: clean build; menus/character select/lodge fill with
user-approved proportions; races render uncropped; pause menu fills.

## HUD edge slide (PR 2)

The race HUD's elements are 0x24-byte layout records (`crates/ssx3-game/
src/ui.rs::HudElem`: short x/y at +0, short w/h at +4, float scale at +8,
float4 colour at +0x10) whose positions every draw reads through
`HUD_GetElemPos` (0x1e91f8). `SSX3_HUD_EDGE` is the edge slide applied
there: a rigid per-side delta in the virtual 640-wide space — elements in
the left third slide left, in the right third right (the 640-x mirror of
the alignment inverts the delta with mirrored elements, so both sides
land correctly), the middle third stays; no clamp (negative coords map
to the true edges — the game's own 2D transform squeezes the HUD space
into the central ~75% of the window, so a delta of 96 moves an element by
~11% of the window's width). Positions only: sizes and spacing untouched
(one delta per side). Races only, not the paused frame (the pause menu
draws its own layout). Verified live: rank, speed, score, the trick
meter, the UBER pole (its pieces read element records too) and the radio
card all slide; 96 = a solid, user-approved edge fit.

**Open (verified live):** the race progress map (the left bar with the
riders' markers, HUD=Full) is drawn by `cOVStateHUD1P_DrawProgressMeter`
(0x20eda0) / `...MP` (0x20fb40) outside the element system — its own
DeferMan records, no element getters, no dedicated matrix. The draw hook,
the record/bucket marking and the renderer transform are staged in a
local-only commit as the basis for a follow-up PR; the full investigation
(the sorted bucket list is empty at hook time, the map appends to
existing buckets via continuation chains, the record-arena route) is in
the engine checkout's `docs/plans/hud-anchor.md`.

## Lesson for future PRs

Commit authorship matters for the GitHub contributors list: the commits
must be authored by the launcher author's account
(`bitm4ncer <175125780+bitm4ncer@users.noreply.github.com>`, the modern
noreply form with the account id), not by the upstream maintainer. PRs
#95/#96 were authored as `andersfischernielsen` (only the committer was
`bitm4ncer`), so the launcher author does not appear in the repo's
contributors. Left as is by decision (no history rewrite, no docs
follow-up); author future commits correctly from the start
(`git -c user.name=... -c user.email=... commit`, and `--reset-author`
when amending).

## Performance note (not engine)

Multi-second stalls mid-race / before jumps came from streaming the disc
image off the pCloud drive (`P:`): the ISO now lives at
`C:\Games\SSX 3\SSX 3 (USA).iso` and the launcher config points there.
First-load stutter after an engine rebuild is the native renderer's
pipeline-cache warm-up (`%LOCALAPPDATA%\SSX3`), not a bug: A/B with the
same binary runs smooth once the cache is warm.
