## Problem

Menus, overlays and the intro are authored at 4:3; in anamorphic
widescreen mode the game renders them pre-squeezed into the central 75% of
the wide frame with black side bars baked in, and no presenter scaling can
remove them. Native 16:9 re-authoring is not viable (no layout system,
3D backdrops with 4:3 cameras, pre-rendered 4:3 video).

## Fix

`SSX3_ASPECT=cover` — the aspect follows the game's own widescreen option
as before, and while the game is in the front end the presenter shows the
central region of the frame filling the window; races and their HUD keep
the full wide frame.

- **Front end detector**: the game's flow word at `gp - 0xb5c`
  (`gp` = register 28; values 0/1 = front end, 2+ = racing and transitions;
  see `ssx3-game/src/game/fe/pluginmenu.rs`). The pause/menu flags at
  `gp - 0x6a0` (bit 1 "frontend", per `audio_system.rs`) turned out to
  never be set on menu screens in practice — the flow word is the
  reliable signal.
- **Presenter crop**: both present shaders (texture path and the `emu-gs`
  buffer path) take a crop uniform (offset x/y, scale x/y) as group 1; the
  vertex stage remaps the fullscreen-triangle UVs, the buffer path's
  fragment stage remaps before footprint averaging. One shared uniform
  buffer serves every pipeline; the settings overlay binds an identity
  crop (never cropped) and the identity is uploaded at creation (an
  unwritten buffer presents black — found the hard way).
- **Geometry**: the menu occupies the central 75% of the frame width at
  full frame height, so the crop shows the central 75% × `fill_h` of the
  frame. `SSX3_MENU_FILL_HEIGHT` tunes `fill_h`: 0.75 is the exact 16:9
  fill (no distortion, cuts ~12% of menu top and bottom); the default
  0.88 trades a small horizontal stretch for keeping the menu's title and
  button hints visible (user-approved proportions). The settings overlay
  lists `cover` (F10).

## Verified

- `cargo check`/`cargo build --profile game -p ssx3`: clean, no warnings.
- Boot → menus fill the window with the user-approved proportions;
  character select and main menu included; anamorphic setting read from
  the save (options word `0x535610` bits 20–21 = 2).
- First-time stutter when loading a player right after an engine rebuild
  is the native renderer's pipeline-cache warm-up
  (`%LOCALAPPDATA%\SSX3\ssx3-wgpu_pipeline_cache_*.bin`), not this change:
  A/B with the same binary runs smooth with `cover` on once the cache is
  warm.
- Still to eyeball before filing (per the roadmap acceptance list):
  pause, results, lodge/shop, intro movie — and the race HUD untouched
  during a real race.
