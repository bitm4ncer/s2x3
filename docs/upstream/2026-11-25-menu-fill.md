# Menu and intro fill for 4:3 front end screens (`SSX3_ASPECT=cover`)

**Status: [local]** — implemented and tested locally on branch `s2x3/menu-fill`
in `C:\Users\konta\Projects\ssx3\ssx3-decomp` (baseline: engine snapshot as
installed by the launcher on 2026-11-25, commit `768f796`; feature commit
`75ee128` + `3d771fc`). No upstream PR yet; the launcher may only rely on
this once it is merged — until then this note gates the launcher's `cover`
choice (`crates/s2x3-engines/src/ps2.rs` already lists it; the engine must
degrade gracefully when the value is unknown, which it does: unknown
`SSX3_ASPECT` values print a warning and follow the game).

## Problem

Menus, overlays (pause, results) and the intro/loading screens are authored
in fixed 4:2D coordinates with 4:3-composed cameras; intro movies are
pre-rendered 4:3 video. In anamorphic widescreen mode the game renders them
as 4:3 content with black side bars baked into the wide frame, so the
presenter cannot scale them away: with the frame stretched to 16:9 the
menus show with black bars on the sides. (`SSX3_ASPECT=cover` was listed as
a launcher choice before the engine supported it.)

Native 16:9 re-authoring is not viable: no layout system (fixed
coordinates), menu backdrops are 3D scenes with 4:3 cameras, intros are
4:3 video.

## Fix (presenter-time crop, engine side)

`SSX3_ASPECT=cover` — aspect follows the game's own widescreen option as
before, and while the game is in the front end the presenter shows the
central 4:3 region of the frame filling the window (cropping top and
bottom); races and their HUD keep the full wide frame.

- `crates/ssx3/src/lib.rs`
  - `game_widescreen(cpu)`: the game's own widescreen option (options word
    at `0x535610`, bits 20–21; 2 = anamorphic). Only then do front end
    screens carry baked-in bars.
  - `frontend_pause(cpu)`: the game's pause/menu flags at `gp - 0x6a0`
    (`gp` = register 28; bit 0 = paused, bit 1 = front end — see
    `audio_system.rs::PAUSE_FLAGS`). Fill is active while either is set.
  - `display_aspect` accepts `cover` (behaves like the default).
  - `show()` computes the crop each frame and calls `Presenter::set_crop`
    / `set_aspect` (aspect 0 = fill the window with the cropped region).
- `crates/ssx3/src/present.rs`
  - Both present shaders (texture path and the `emu-gs` buffer path) take a
    crop uniform (offset x/y, scale x/y) as group 1; the vertex stage
    remaps the fullscreen-triangle UVs, the buffer path's fragment stage
    remaps before footprint averaging.
  - One shared uniform buffer + bind group serves every pipeline; the
    settings overlay binds an identity crop (never cropped). The identity
    is uploaded at creation (an unwritten buffer presents black — found
    the hard way).
  - `Presenter::set_crop(Option<[f32; 4]>)` uploads on change only.
- Crop geometry: central 75% × 56.25% of the frame = the 4:3 content of a
  16:9-stretched frame, displayed filling the window (cropping top and
  bottom). Fractions are aspect-independent, so they hold for the native
  renderer's window-sized image too.
- `crates/ssx3/src/settings.rs`: the F10 overlay lists `cover`.

## Verification so far

- `cargo check`/`cargo build --profile game -p ssx3`: clean, no warnings.
- Boot to the attract demo in a window with `SSX3_ASPECT=cover`: the game
  renders and presents (the initial black-screen bug was the missing crop
  identity upload, fixed in `3d771fc`).
- Still to verify (needs eyes on the live game): main menu, character/
  peak select, pause, results, lodge/shop, intro filling the width without
  distortion, and races + HUD unchanged. The game's own widescreen option
  must be anamorphic for the bars to exist (fresh install defaults need
  checking — the attract reel measured 4:3 content with thin bars).

## How to test locally

Point the launcher's `engine.root` at the checkout, or run:

```
cd ~/Projects/ssx3/ssx3-decomp
SSX3_ISO=<iso> SSX3_MEMCARD=<saves>/ssx3-mc0.ps2 \
SSX3_SETTINGS=<saves>/ssx3-settings.cfg SSX3_ASPECT=cover \
cargo run --profile game -p ssx3
```
